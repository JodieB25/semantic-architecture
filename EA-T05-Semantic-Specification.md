# 1. Purpose

This Semantic Specification defines the authoritative semantic meaning of the EA-T05 Enterprise Operating Context Semantic Object.

It is the normative semantic authority governing the interpretation of Enterprise Operating Context and establishes the semantic boundaries within which downstream artefacts shall operate.

This specification defines:

- the canonical semantic subject;
- the semantic container and semantic anchor;
- the governed semantic scope;
- semantic ownership boundaries;
- semantic decomposition;
- canonical semantic outcomes;
- semantic invariants;
- upstream and downstream semantic relationships; and
- the canonical Enterprise Operating Context semantic state.

This specification is implementation independent.

It governs semantic meaning only.

It does not govern:

- information acquisition;
- semantic evaluation;
- semantic assertions;
- semantic compilation;
- canonical output rendering;
- implementation architecture;
- software behaviour; or
- presentation.

Those responsibilities are governed by downstream specifications.

The semantic meaning established by this specification is derived from the EA-T05 Semantic Object and elaborated through the Enterprise Operating Context Knowledge Architecture.

Accordingly, this specification forms the normative semantic authority from which the following artefacts shall be derived without redefining semantic meaning:

- Knowledge Architecture;
- Semantic Assertion Contract;
- Semantic Input Pattern;
- Semantic Evaluation Specification;
- Semantic Compilation Specification; and
- Canonical Semantic Model.

No downstream artefact may redefine the semantic meaning established by this specification.

All downstream artefacts SHALL consume this specification as the single semantic authority for Enterprise Operating Context.
# 2. Semantic Subject

The semantic subject of EA-T05 is the **Enterprise Operating Context**.

Enterprise Operating Context is the canonical semantic representation of the operating circumstances under which a Reporting Entity performs one exact Applicable Designated Service Operating Configuration.

It establishes the complete factual operating context required to describe **how** an applicable Designated Service is performed without determining:

- Enterprise identity;
- Enterprise Service semantics;
- Designated Service applicability;
- Reporting Entity establishment;
- governance;
- ML/TF assessment;
- understanding;
- judgement;
- response; or
- AML/CTF Program behaviour.

The semantic subject is represented by one governed semantic container.

## Canonical Semantic Container

The canonical semantic container is:

> **Applicable Designated Service Operating Configuration**

The container represents one exact operating configuration for one applicable Designated Service.

Every semantic assertion governed by EA-T05 SHALL attach either:

- directly to this container; or
- to an exact qualified target contained within this container.

The semantic container organises Enterprise Operating Context.

It does not own the semantic meaning of referenced upstream entities.

## Canonical Semantic Anchor

The semantic anchor for EA-T05 is also:

> **Applicable Designated Service Operating Configuration**

The anchor provides the unique semantic attachment point for every governed Enterprise Operating Context assertion.

It exists solely to organise semantic composition.

It SHALL NOT:

- replace Enterprise identity;
- replace Enterprise Service Arrangements;
- replace Designated Services;
- replace Reporting Entity identity;
- replace Customer identity;
- replace Delivery Channel identity;
- replace Operating Arrangement identity; or
- replace any other upstream semantic authority.

# 3. Canonical Question

> **What is the complete Enterprise Operating Context for this Applicable Designated Service Operating Configuration?**

The canonical semantic question is answered by establishing the complete canonical semantic state describing the operating context applicable to one exact Applicable Designated Service Operating Configuration.

The canonical question is intentionally constrained.

It does not ask:

- who the Enterprise is;
- what Enterprise Services exist;
- whether a Designated Service exists;
- whether the Enterprise is a Reporting Entity;
- whether governance obligations exist;
- whether ML/TF risks exist;
- whether suspicious circumstances exist; or
- what operational or regulatory response should occur.

Those questions are governed by separate Semantic Objects.

The EA-T05 canonical question is limited exclusively to the factual operating context within which an already-established Applicable Designated Service Operating Configuration exists.

Accordingly, successful evaluation SHALL establish only the semantic state necessary to describe that operating context.

# 4. Semantic Scope

EA-T05 governs the semantic meaning of Enterprise Operating Context.

Enterprise Operating Context establishes the complete factual operating context applicable to one exact Applicable Designated Service Operating Configuration.

The scope of EA-T05 is limited to semantic meanings that qualify, relate, or describe the operating circumstances under which an applicable Designated Service is performed.

The scope is intentionally independent of:

- legislative identity;
- legislative applicability;
- governance;
- assessment;
- judgement;
- operational response; and
- implementation.

The semantic scope is organised into eight governed semantic domains.

---

## 4.1 Designated Service Operating Characteristics

This semantic domain governs the characteristics that qualify the manner in which an Applicable Designated Service is provided.

The domain establishes:

- Delivery Means Characteristic;
- associated qualification semantics;
- semantic participation within the operating configuration.

This domain qualifies service operation.

It does not establish Designated Service identity.

---

## 4.2 Customer Kind and Relationship Characteristics

This semantic domain governs the customer operating context participating within the Applicable Designated Service Operating Configuration.

The domain establishes:

- Customer Kind;
- Customer Relationship;
- mandatory customer participation;
- customer relationship topology.

Customer identity remains an upstream semantic authority.

EA-T05 governs only the operating-context participation of those upstream semantic subjects.

Every valid Enterprise Operating Context SHALL include:

- at least one Customer Kind; and
- at least one Customer Relationship.

---

## 4.3 Delivery Channel Characteristics

This semantic domain governs the operative relationship between the Applicable Designated Service Operating Configuration and the Delivery Channel through which the service is performed.

The scope includes:

- Service–Channel Relationship;
- delivery-channel participation;
- channel applicability.

Delivery Channel identity remains upstream.

EA-T05 governs only the semantic operating relationship.

---

## 4.4 Geographic Connection Characteristics

This semantic domain governs the role-specific geographic qualifications applicable to the operating configuration.

The scope includes:

- Geographic Connection Qualification;
- role-specific geographic participation;
- exact qualified targets.

Countries, jurisdictions and places remain upstream semantic authorities.

EA-T05 governs only their operating-context qualification.

---

## 4.5 Transaction and Value Characteristics

This semantic domain governs:

- Transaction Qualification; and
- Value Qualification.

These semantic subjects preserve:

- transaction structure;
- transaction predicates;
- transaction relationships;
- quantitative value characteristics; and
- exact semantic attachment.

Transaction identity remains upstream.

EA-T05 governs only the operating-context qualification of those transactions.

---

## 4.6 Operating Arrangement Characteristics

This semantic domain governs the semantic relationship between the Applicable Designated Service Operating Configuration and the Operating Arrangement through which it is performed.

The scope includes:

- Service–Arrangement Relationship;
- arrangement participation;
- arrangement topology.

Operating Arrangement identity remains upstream.

EA-T05 governs only operating-context participation.

---

## 4.7 Operating State, Scale and Change Characteristics

This semantic domain governs:

- Operating State;
- Operating Scale; and
- Operating Change.

These semantic authorities remain distinct.

The specification explicitly prohibits their collapse into a single operating characteristic.

Each semantic authority qualifies one exact operating target.

---

## 4.8 Conditional Operating Enrichment

This semantic domain governs the conditional participation of referenced upstream semantic authorities required to complete an operating-context composition.

Conditional Operating Enrichment governs:

- activation conditions;
- participation topology;
- semantic attachment.

It does not establish any independent endpoint meaning.

All enriched semantic meanings remain owned by their originating semantic authorities.

---

## Governing Semantic Structure

Collectively these eight semantic domains establish the complete semantic scope of Enterprise Operating Context.

No semantic meaning outside these domains is governed by EA-T05.

No additional semantic domain may be introduced without amendment to the governing Semantic Object.

---

## Scope Constraints

The semantic scope SHALL preserve the following architectural constraints:

- operating-context semantics remain factual;

- implementation concerns remain excluded;
- downstream semantic conclusions remain excluded.
